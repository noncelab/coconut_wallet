# CCOS 기능 경계

영문 버전: [feature_boundary.en.md](./feature_boundary.en.md)

이 문서는 기여자가 CCOS에 제안하거나 PR할 수 있는 기능의 경계를 쉽게 판단할 수 있도록 정리한 문서예요.

먼저 읽어 보시면 좋은 문서:

- [architecture.md](../foundation/architecture.md)

## 1. 목적

기여자가 떠올린 기능이 CCOS에 들어갈 수 있는지 미리 가늠할 수 있어야 해요.

이 문서는 아래 목적을 가지고 있어요.

- 허용 가능한 기능과 금지되는 기능을 공개적으로 나눠 보여줘요.
- 코코넛 개발팀 검토가 조금 더 일관되게 이루어지도록 도와줘요.
- 지갑이 안전하게 동작하기 위해 지켜야 하는 핵심 범위를 기여자가 이해하기 쉬운 방식으로 분명하게 보여줘요.

## 2. 경계 범주

### Green `🟢`

기여자가 비교적 자유롭게 제안하고 PR할 수 있는 범주예요.

조건:

- 지갑 핵심 로직을 수정하지 않아요.
- 보안에 민감한 경로를 건드리지 않아요.
- 안전하게 분리해 둔 영역 안에서 끝나거나, 미리 허용한 범위를 넘지 않아요.
- 외부 통신이나 외부 저장소 의존 없이도 기능이 동작해요.

예시:

- 분석 화면: 지갑 데이터를 바깥으로 보내지 않고, 이미 가진 정보를 보기 좋게 보여주는 화면
- 내보내기 화면: 이미 지갑 안에 있는 정보를 사용자가 확인하고 앱 밖으로 공유하거나 옮길 수 있게 하는 화면
- 로컬 요약 화면 또는 대시보드: 기기 안에 있는 정보를 바탕으로 상태를 정리해 보여주는 화면
- 알림 관련 UI: 알림 설정이나 알림 내용을 화면에서 보여주는 UI
- 위젯처럼 보여주는 화면 모듈: 정보를 카드나 위젯처럼 빠르게 볼 수 있게 정리한 화면 요소

### Yellow `🟡`

사전 검토가 필요한 범주예요.

조건:

- 외부 통신, 외부 저장, 개인정보와 신뢰에 영향을 주는 지점, 의존성 위험이 있어요.
- 코코넛 월렛의 신뢰성이나 장기 유지보수 비용에 영향을 줄 수 있어요.

예시:

- 네트워크 통신: 코코넛 월렛 밖의 서버나 서비스와 데이터를 주고받는 기능
- 외부 API 연동: 외부 서비스 응답에 기대어 기능이 동작하는 화면이나 기능
- 영구 저장소 사용: 앱 밖이나 별도 저장소에 데이터를 계속 남겨 두는 기능
- 규모가 큰 서드파티 의존성 추가: 앱의 동작과 유지보수에 영향을 줄 수 있는 외부 라이브러리 추가
- 백그라운드 동작 변경: 앱이 열려 있지 않을 때도 갱신이나 실행이 필요해, 앱의 동작 방식에 영향을 주는 변경

운영 규칙:

- 구현 PR부터 바로 올리지 않아요.
- 먼저 제안을 공유하고, 구조 / 개인정보 / 유지보수 관점에서 검토를 받아요.

### Red `🔴`

CCOS 기여 기능으로는 받지 않는 범주예요.

조건:

- 지갑이 안전하게 동작하기 위해 지켜야 하는 핵심 범위를 직접 흔들어요.
- 핵심 무결성이나 보안 전제를 약화시켜요.

예시:

- 지갑 데이터베이스 구조 변경: 지갑 안에 저장되는 핵심 데이터 구조 자체를 바꾸는 작업
- 지갑 동기화 방식 변경: 지갑이 블록체인 상태를 받아오고 맞추는 방식을 바꾸는 작업
- 지갑 식별자, 주소 파생, UTXO 해석, 트랜잭션 구성 방식 변경: 지갑이 자산 상태를 이해하고 보여주는 핵심 동작을 바꾸는 작업
- 브로드캐스트 / 수수료 정책 변경: 트랜잭션 전송 방식이나 수수료 결정 방식에 손대는 작업
- 지갑 데이터 수집을 전제로 하는 기능: 지갑 데이터를 모으거나 분석 대상으로 삼아야만 성립하는 기능

## 3. 경계 확인 질문

모든 제안은 아래 질문으로 먼저 가볍게 분류해 보세요.

1. 지갑 핵심 로직을 직접 수정하나요?
2. 지갑 데이터를 외부 시스템과 연결하거나 바깥에 저장하나요?
3. 새로운 신뢰 / 개인정보 / 보안 지점을 열게 되나요?
4. 안전하게 분리된 확장 영역 안에서 설명할 수 있나요?
5. UI 중심 기능으로 끝나거나, 미리 정해 둔 허용 범위 안에서 마무리되나요?

판정 기준:

- 4, 5가 중심이면 Green일 가능성이 높아요.
- 2, 3이 포함되면 Yellow 또는 Red 검토가 필요해요.
- 1이 포함되면 기본적으로 Red로 봐요.

## 4. 기여 범위 밖의 영역

다음 영역은 일반 기여 기능의 범위 밖으로 봐요.

- 앱 시작 설정
- 라우트 연결 구조
- Provider 연결 구조
- 전역 테마 연결 구조
- 지갑 핵심 코드와 보안에 민감한 코드

코드 경로 예시:

- `lib/core/**`
- `lib/services/**`
- `lib/repository/realm/**`
- `lib/providers/node_provider/**`

## 5. 검토 결과

모든 제안은 보통 아래 셋 중 하나로 정리돼요.

- `Green으로 진행`
- `Yellow 검토 필요`
- `Red로 보류 또는 반려`

## 6. 참고

- 권장 예시는 Green 범주만 다뤄요.
- Yellow 범주는 기본 기여 경로에 바로 포함하지 않아요.
- Red 범주는 제안 단계에서 걸러질 가능성이 크지만, 효용이 매우 크다면 별도 검토 대상이 될 수 있어요.
