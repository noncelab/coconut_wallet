# 제안 기능 유료화 가이드

영문 버전: [monetization_guide.en.md](./monetization_guide.en.md)

이 문서는 기여자가 제안하는 기능의 유료화를 원하는 경우 어떤 절차를 거치는지 정리했어요.

먼저 읽어 보시면 좋은 문서:

- [feature_boundary.md](../getting_started/feature_boundary.md)

기여자는 기능을 무료로 제안할 수도 있고, 기여자의 개발 활동을 지속 가능하게 만드는 방식의 유료화를 제안할 수도 있어요. CCOS는 이 두 방향을 모두 지원하는 것을 목표로 해요.

## 1. 유료화 정책 현황

현재 제안 기능의 유료화 논의를 거쳐, 실제 유료 기능으로 배포될 수 있어요. 코코넛 개발팀이 검토를 거쳐, 배포 시점에 결제를 직접 연동하는 방식이에요.

지금 단계에서 결정된 것과 아직 결정되지 않은 것을 나눠서 밝힐게요.

- 결정된 것: 어떤 유료화 방식을 선택할 것인가 (무료 / 1회 구매 / 구독 등)는 아래 "현재 지원하는 것" 기준으로 코코넛 개발팀과 함께 정해요.
- **아직 결정되지 않은 것**: 코코넛 개발팀과 기여자가 계약을 진행하는 공식 절차는 아직 문서화되어 있지 않아요. 지금은 2장의 "제안 절차"를 통해 건별로 논의해요. `[TODO: 계약 절차가 정식화되면 여기 별도 문서로 링크]`

향후 시장성이 검증되면, 기여자 대시보드 같은 도구로 계약·정산 절차를 자동화할 계획이에요. (로드맵이며, 상황에 따라 계획이 변경될 수 있어요.)

### 현재 지원하는 것

- 무료 / 1회 구매 / 구독 / 향후 유료화 후보로 분류하는 문서
- 유료화 관련 정보 표시 규칙 정의
- 유료 기능 후보 검토 기준 정의
- 코코넛 개발팀과의 수동 논의를 통한 유료 기능 제안과 실제 결제 연동 (배포 시 개발팀이 직접 연동해요)
- 판매가 발생했을 때 기여자에게 정산할 기준 정의
  - 정산 기준 자체는 내부 기준으로 관리하며 전체 공개 문서화는 하지 않지만, 제안 시점에 담당자가 기여자에게 개별 안내해요. 문의 채널: `[TODO: 정산 기준 문의 창구 명시]`
- 임시 구매 흐름 설계 초안
- 스토어 표시 정보와 활성화 / 사용 권한 상태를 분리하는 구조 정의
- 사용자가 "누가 만든 기능인지"와 "어떤 가격 정책 후보인지"를 함께 이해할 수 있는 카드 구조 초안

### 현재 지원하지 않는 것

- 기여자가 직접 결제 시스템을 연동하는 것
- 신규 유료 기능을 결제 / 사용 권한 파이프라인에 자동으로 연결하는 것 (지금은 기능마다 코코넛 개발팀이 직접 연동해요. 일단 연동되고 나면 개별 구매 건의 사용 권한 발급 자체는 배포 버전에서 자동으로 이뤄져요)
- 자동화된 구독 주기 관리
- 계약 절차를 모든 기여자에게 공개적으로 문서화하는 것
- 기여자 대시보드를 통한 자동 정산 (로드맵이며, 상황에 따라 계획이 변경될 수 있어요)

3. 범위 안이라고 판단되면, 코코넛 개발팀과 기여자가 유료화 방식(무료 / 1회 구매 / 구독)과 정산 기준을 개별 논의해요.

## 3. 검토 질문과 판정

아래 질문은 코코넛 개발팀이 유료 기능 제안을 검토할 때 쓰는 기준이에요. 기여자도 제안 전에 스스로 먼저 점검해 보면 좋아요.

1. 이 기능이 기여자가 직접 구현하는 자동화된 결제 연동을 요구하는가, 아니면 코코넛 개발팀과의 수동 논의로 연동할 수 있는 수준인가?
2. 앞으로의 유료화를 위한 정보와 정책을 제안하는 수준인가?
3. 기여자가 유료화 범위를 오해할 여지가 있는가?
4. 가격 표시가 작성자 / 의도 / 경계 정보를 가리고 있지는 않은가?
5. 앱 재실행 후 사용 권한과 활성화 상태를 다시 계산할 수 있는 구조인가?

판정 (코코넛 개발팀 기준):

- 정책 / 문서 / 표시 정보 / 코코넛 개발팀과의 수동 결제 연동 수준이면 현재 범위에서 가능해요.
- 기여자가 직접 구현하는 자동화된 결제 연동이면 현재 범위 밖이에요.

## 4. 기여자 안내

- 유료화는 구현 자체보다는 범위와 정책 관점에서 먼저 제안해 주세요. 제안 방법은 2장을 참고해 주세요.
- 결제 수단이나 사업자 정보를 제안 시점에 미리 준비할 필요는 없어요. 유료화 방식과 정산 기준은 제안이 승인된 뒤 코코넛 개발팀과 개별로 정해요.
- 코코넛 오픈 스토어에서 유료 기능을 어떻게 표시할지에 대한 세부 원칙은 아직 코코넛 개발팀이 설계 중이에요. 확정되면 이 문서에 반영할게요.
