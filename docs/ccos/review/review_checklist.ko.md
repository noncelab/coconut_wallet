# 제안 기능 리뷰 체크리스트

영문 버전: [review_checklist.en.md](./review_checklist.en.md)

이 문서는 제안된 기능을 리뷰할 때 확인해야 할 기본 체크리스트예요.

## 1. 경계

- 기능이 Green / Yellow / Red 중 어디에 속하는지 명시되었는가
- 그렇게 분류한 이유가 적혀 있는가
- Red 영역을 건드리지 않는가

## 2. 안전성

- 지갑 핵심 로직을 수정하지 않는가
- 보안에 민감한 경로를 건드리지 않는가
- 새로운 개인정보 또는 보안 관련 위험 지점을 만들지 않는가

## 3. 구조

- 코코넛 월렛의 테마 / 토큰 / 기본 UI 규칙을 따르는가
- 기여자가 수정할 수 있는 범위 안에서 설명 가능한가
- 공식 경로와 폴더 구조를 따르는가
- 처음 도입된 카테고리라면, registry 등록뿐 아니라 실제 진입점(host surface) 구현이 같은 PR에 포함되어 있는가 (`foundation/architecture.md` 6.1절). 단, 그 진입점이 테마 예시(`theme_bottom_sheet.dart`)와 구조가 다르다는 이유만으로 반려하지 않는다 — 카테고리마다 다른 진입점은 의도된 것이다.
- PR에 실제 entitlement 연동 코드(구매 버튼, 결제 파이프라인, 영수증 검증 등)가 포함되어 있지는 않은가 — 있다면 정상이 아니다. 그건 기여자의 역할이 아니라 계약 체결 후 코코넛 개발팀이 배포 시점에 직접 담당하는 부분이다 (`foundation/architecture.md` 6.2절)

## 4. 테스트

- 기능에 맞는 테스트가 추가되었는가
- 테스트를 추가하지 않았다면 이유가 분명하게 적혀 있는가
- 변경된 기능을 어떻게 수동 검증했는지 확인할 수 있는가

## 5. 문서

- 필요한 문서 업데이트가 같이 포함되었는가
- 기여 시작 문서의 내용과 충돌하지 않는가

## 6. 범위

- Yellow 기능이라면 사전 검토 기록이 있는가

## 7. 머지 후 처리 (리뷰어/머지 담당자용)

- 머지 직후 기여자에게 안내를 보냈는가 (기본은 GitHub 코멘트, 유료 기능 제안이었다면 남겨진 이메일로도)
- 유료 기능이라면 계약 절차(`foundation/monetization_guide.md`)를 시작할 담당자를 지정했는가
- 이 변경이 다음 배포 버전에 포함된다는 것을 기여자에게 안내했는가 (즉시 반영이 아니라는 점)

세부 절차는 코코넛 개발팀 내부 가이드를 따른다.
