# PIN verifier 및 시도 제한

## 구현 정책

- 신규 설정·변경: Argon2id v19, 메모리 19MiB(19,456 KiB), 반복 2, 병렬도 1, 결과 32바이트.
- 각 설정에 `Random.secure()`로 새 16바이트 salt를 생성한다. 4·6자리 ASCII 숫자와 선행 0을 유지한다.
- 기존 `cryptography` 2.7.0 구현을 사용한다. KDF는 별도 isolate에서 수행한다. 새로운 네이티브/외부 패키지 의존성은 없다.
- 비용은 [OWASP 지침](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html#argon2id)의 최소 설정을 적용했다. 지원 대상 저사양 기기도 추가 측정해야 한다.
- PIN은 저장하지 않는다. Secure Storage의 `pin_auth_v1` 단일 JSON 레코드에 저장 버전, 알고리즘·비용·PIN 길이·salt·verifier·실패 횟수·다음 시도 시점·마지막 관측 시점을 함께 저장한다.
- 알 수 없는 버전/알고리즘, 변경된 비용, 잘못된 바이트 길이 및 손상된 레코드는 인증 오류로 처리한다. 값이 손상되어도 레거시 SHA-256으로 돌아가지 않는다.

## 인증·시도 제한

모든 PIN 인증은 `AuthProvider.verifyPinResult()` → `PinAuthService.verify()`를 사용한다. 인증 작업은 동시에 한 개만 실행한다. 중복 요청은 `busy`로 반환하고 추가 KDF를 실행하지 않는다.

실패 시 볼트와 동일하게 “n번 다시 시도할 수 있어요”, 대기 중에는 “n 후 재시도 할 수 있어요”를 표시한다. 남은 시간은 시간·분·초로 나눈다. 매 회차 3번의 입력 기회를 제공한다. 세 번째 실패/중단에서만 아래 대기를 적용하며, 대기 종료 후 다음 회차의 기회 3번이 생긴다. 회차와 진행 중 실패 횟수는 누적 실패 수로 계산하므로 화면/앱 재진입으로 추가 기회가 생기지 않는다.

| 대기 회차 · 누적 실패/중단 | 다음 시도 지연 |
| --- | --- |
| 1회차 · 3회 | 30초 |
| 2회차 · 6회 | 60초 |
| 3회차 · 9회 | 120초 |
| 4회차 · 12회 | 240초 |
| 5회차 · 15회 | 480초 |
| 6회차 이상 · 18, 21, 24…회 | 900초 |


KDF **실행 전** 실패 횟수와 지연을 저장하고 읽어서 확인한다. Android의 `flutter_secure_storage` 9.x가 `SharedPreferences.apply()`를 사용하므로, 별도 백그라운드 MethodChannel에서 저장 키와 암호화 저장소에 빈 `commit()`을 수행해 디스크 저장 완료도 확인한다. 채널에는 인증 값을 전달하지 않는다. 이 처리는 [Android 공식 문서의 apply/commit 동작](https://developer.android.com/reference/android/content/SharedPreferences.Editor#apply())을 따른다. 플러그인 저장 파일명이 바뀌는 업그레이드에서는 네이티브 처리를 함께 검토해야 한다. 따라서 검증 도중 강제 종료한 요청도 시도를 소비한다. 올바른 PIN 인증이 성공하면 상태를 초기화한다. 저장·읽기·KDF 실패 시 성공을 반환하지 않는다.

볼트와 동일하게 저장된 잠금 해제 시각(`nextAllowedAt`)과 `DateTime.now()`를 비교한다. 앱을 닫아 둔 시간도 경과 시간에 포함하고, 재실행 시 지연을 다시 부과하거나 해제 시각을 조정하지 않는다. UI 카운트다운도 동일한 절대 시각을 사용한다. 따라서 시스템 시각을 앞당기면 시간 기반 대기를 우회할 수 있고, 뒤로 돌리면 대기가 길어질 수 있다. 별도의 시계 조작 방지는 적용하지 않는다. PIN 변경·삭제 권한의 5분 유효기간은 시도 제한과 별개이며 기존 단조 증가 시간 기준을 유지한다.

생체인증은 기존처럼 별도로 허용한다. 볼트처럼 생체인증 성공 시 저장된 PIN 실패 횟수와 잠금 해제 시각을 초기화한다. 초기화 저장이 완료된 뒤 인증 성공을 반환한다. PIN을 알 수 없으므로 verifier는 이전하지 않는다. 성공한 PIN/OS 생체인증은 5분간 PIN 변경·삭제를 허용하고, 변경·삭제 후 권한을 소비한다. 신규 PIN이 기존 PIN과 같은지 확인하는 과정은 로그인 실패로 계산하지 않는다.

## 기존 사용자 이전 및 중단 대응

1. `pin_auth_v1`이 없으면 Secure Storage의 기존 `pin` SHA-256 verifier를 읽고, 제한 상태를 포함한 레거시 레코드를 작성·확인한다.
2. 올바른 PIN 입력 후 새로운 salt와 Argon2id verifier를 만든다.
3. 단일 새 레코드에 성공 상태를 기록하고 읽어서 확인한다.
4. 레거시 `pin` 키를 제거한다. 삭제까지 성공한 뒤 인증 성공을 반환한다.

저장 실패/강제 종료 시 기존 PIN으로 재시도할 수 있다. 새 레코드가 있으면 레거시 키가 남아 있더라도 새 레코드만 사용한다. 이전이 끝나면 약한 SHA-256 verifier를 남기지 않는다. 생체인증만 사용하는 사용자는 첫 PIN 인증까지 레거시 verifier를 유지한다.

기존 설치의 시작 시 Secure Storage에서 PIN 설정 여부·길이를 확인해 SharedPreferences의 표시용 메타데이터를 보완한다. PIN 저장 직후 앱이 종료되어 설정 플래그가 남지 않은 경우에도 잠금을 건너뛰지 않는다. 저장소를 읽을 수 없으면 잠금을 유지한다. 신규 설치에서는 iOS Keychain 잔존 데이터를 지우는 기존 온보딩을 유지하고 이전 설치의 PIN을 복원하지 않는다. 앱 재설치·저장소 전체 초기화는 시도 제한 보존 범위에 포함하지 않는다. PIN 삭제는 레거시 키를 먼저 삭제하여 중단 시 약한 verifier가 복구되지 않도록 한다. 전체 초기화도 검증과 직렬화한다.

신규 verifier를 지원하지 않는 이전 앱 버전으로 다운그레이드하는 것은 지원하지 않는다. 레거시 verifier를 롤백용으로 유지하지 않는다. 문제 발생 시 신규 형식을 읽는 수정 버전으로 전진 배포한다. PIN 분실 시 기존의 명시적 전체 초기화 흐름을 사용하며, 실패 횟수로 지갑이나 시드를 자동 삭제하지 않는다.

## 민감 데이터·로그

PIN/hash/salt/KDF 결과/verifier/인증 레코드는 디버그 로그·분석 이벤트·오류 보고·예외 메시지에 넣지 않는다. 인증 경계에서 플랫폼·저장·KDF 예외를 고정 오류 코드로 바꾼다. 기존 인증/생체인증 관련 예외 로그도 고정 메시지로 변경했다.

메인 isolate와 작업 isolate에서 소유한 PIN·salt·결과 바이트 사본은 `finally`에서 덮어쓴다. 입력 필드의 String 참조는 성공·종료 시 제거한다. Dart 런타임과 암호 라이브러리 내부의 불변 사본까지 완전히 삭제한다고 보장하지 않는다.

KDF는 추출된 verifier의 오프라인 대입 비용을 높인다. 앱 시도 제한은 앱 내 인증에 적용된다. 루팅/탈옥, Secure Storage 변조·전체 스냅샷 복구, 외부 오프라인 대입까지 앱의 제한으로 막을 수는 없다.

- 시작: PIN 메타데이터 갱신 전 종료·레거시 설정·읽기 실패 시 잠금 유지 및 신규 설치 온보딩 호환성.
- Android 저장 완료: 채널이 인증 값을 전달하지 않음, 디스크 저장 대기, 실패·채널 부재 시 인증 차단.

### PIN 변경·해제 중단 시 일관성

- PIN 해제는 verifier를 포함하지 않는 명시적 `disabled` 레코드를 저장한다. 시작 시 이 기록이 있으면 PIN·생체인증 표시 메타데이터를 해제하고 PIN 길이를 제거한다. 단순한 레코드 누락으로 기존 잠금을 해제하지 않는다.
- PIN 변경은 새 verifier 계산 후 레거시 키를 정리하고 마지막으로 새 레코드를 저장한다. 정리 실패 시 기존 PIN을 유지한다. 새 레코드 저장·확인 실패 시 이전 레코드를 복구한다. 복구도 실패하면 변경 권한을 폐기하고 저장 상태 확인 불가를 별도 안내한다. 저장 중 앱 종료 시에는 다음 시작에서 실제 보안 레코드의 상태·길이를 복구한다.
- 보안 저장 완료 후 표시용 SharedPreferences 갱신 오류는 PIN 저장 실패로 표시하지 않는다. 메모리 상태는 저장된 PIN에 맞추고 다음 시작 시 메타데이터를 복구한다.
- 변경 권한 만료 시 이전 화면에서 재인증하도록 안내한다.

### 전체 초기화 중단 복구 및 잠금 해제 오류

- 사용자가 전체 초기화를 승인하면 `APP_RESET_PENDING`을 먼저 저장한다. 보안 저장소, Realm 지갑 데이터, 초기화 대상 설정을 순서대로 지운 후 마지막에 이 표시를 제거한다. 저장 성공 여부도 확인한다.
- 다음 시작 시 표시가 남아 있으면 앱 화면을 열기 전에 전체 초기화를 다시 수행한다. 표시만 보고 PIN 잠금을 해제하지 않는다. 복구 실패 시 표시를 유지하고 앱 시작을 중단하여 남은 지갑 데이터에 접근하지 못하게 한다.
- 정상 시작 시에는 전체 초기화를 수행하지 않는다. 이 표시는 초기화 대상 설정 목록에 포함하지 않는다.
- 설정 화면의 앱 잠금 해제 실패는 CoconutPopup으로 안내한다. 인증 만료는 재인증 안내, 저장 상태 불확실은 앱 재실행 안내, 일반 오류는 처리 실패 안내를 표시한다. 팝업을 닫은 뒤 다시 시도할 수 있다.
- 회귀 테스트: `app_reset_service_test.dart`(초기화 중단·복구 실패·정상 시작), `app_lock_failure_test.dart`(오류별 안내·재시도).
