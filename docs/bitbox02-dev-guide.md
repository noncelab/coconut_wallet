# BitBox02 Integration — Developer Guide

Coconut Wallet ↔ BitBox02 Nova (BTC-only) hardware wallet via gomobile bridge.

---

## 1. Environment Setup

### Prerequisites

| Tool | Version | Notes |
|---|---|---|
| Go | 1.22+ | `brew install go` |
| gomobile | latest | `go install golang.org/x/mobile/cmd/gomobile@latest` |

## 3. Build Instructions

### 3.1 Go Bridge → AAR

```bash
cd go
gomobile bind \
  -target=android \
  -androidapi 21 \
  -o ../android/app/libs/bitboxbridge.aar \
  .
```

**Output:** `bitboxbridge.aar` (~23MB) + `bitboxbridge-sources.jar` (~7KB)

**Method naming:** Go `BTCPub` → Kotlin `btcPub`, Go `ConnectWithInfo` → `connectWithInfo`

## 4. Simulator Setup (Docker + TCP)

### 4.1 Download Simulator Binary

BitBox02 multi-coin simulator v9.26.1 from the official GitHub releases:
`https://github.com/BitBoxSwiss/bitbox02-firmware/releases`

Place it at `simulator/bitbox02-simulator`.

### 4.2 Build Docker Image

```bash
cd simulator
docker build -t bitbox02-simulator .
```

### 4.3 Run Simulator

```bash
docker run -d --name bitbox02-sim -p 15423:15423 bitbox02-simulator
```

### 4.4 Verify Simulator is Responding

```bash
# Send a U2F HID init frame, expect CID 0xFF000000 response
echo -n -e '\x00\x00\x00\xff\xc1\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00' | nc localhost 15423 | xxd | head -1
# → 00000000: ff00 0000 ... (CID in response)
```

### 4.5 Connect from Android Emulator

The emulator sees the host machine at `10.0.2.2`.

In the connect screen, use **"Connect via Simulator (TCP)"** which connects to `10.0.2.2:15423`.

The simulator doesn't provide USB HID descriptors, so `ConnectWithInfo` is used:
- `product`: `"btc-only"` or `"multi"`
- `version`: `"9.26.1"`

## 6. gomobile Bugs & Workarounds

### 6.1 `Read(p []byte)` — Copy-Back Bug

**Bug:** When Go calls `io.ReadWriteCloser.Read(p []byte)` across the gomobile boundary, Java/Kotlin modifies `p` in place, but Go sees all zeros. gomobile does NOT copy back the modified buffer.

**Symptom:** `io.ReadAll` returns `[]byte{0,0,0,...}` — zeros, not firmware data.

**Solution:** Changed `Transport` interface to return a new byte slice:

```go
// BEFORE (broken)
type Transport interface {
    Read(p []byte) (int, error)  // Java writes to p, Go sees zeros
}

// AFTER (working — matches bitbox-wallet-app pattern)
type Transport interface {
    Read(n int) ([]byte, error)  // Java returns new byte[], Go receives it
}
```

The adapter in `transport.go` copies from the returned slice into the `io.Reader` buffer:

```go
func (a *transportAdapter) Read(p []byte) (int, error) {
    data, err := a.t.Read(len(p))
    if err != nil { return 0, err }
    return copy(p, data), nil
}
```

### 6.2 Kotlin Implementation of `Read(n: Long): ByteArray`

```kotlin
// Bitboxbridge.aar generates:
class Transport {
    fun read(n: Long): ByteArray  // n is Long (Go int → Kotlin Long)
    fun write(p: ByteArray): Long
    fun close()
}
```

### 6.3 `NetworkOnMainThreadException`

**Bug:** gomobile proxies Java calls on the calling thread. MethodChannel handlers run on the main thread, so any Bridge I/O (Read/Write, which triggers network/socket) throws `NetworkOnMainThreadException`.

**Solution:** All Bridge methods dispatched to a single-thread `ExecutorService`:

```kotlin
private val executor = java.util.concurrent.Executors.newSingleThreadExecutor()
private val mainHandler = Handler(Looper.getMainLooper())

private fun <T> runOnExecutor(result: MethodChannel.Result, block: () -> T) {
    executor.execute {
        try {
            val value = block()
            mainHandler.post { result.success(value) }
        } catch (e: Exception) {
            mainHandler.post { result.error("BB02_ERROR", e.message, null) }
        }
    }
}
```

### 6.4 Disposed VM: `dispose()` Must Not Await Async Operations

**Bug:** Calling `device.disconnect()` (which is async) inside ViewModel `dispose()` causes state updates after the VM is already disposed.

**Solution:** Fire-and-forget in `dispose()` — don't await disconnect:

```dart
@override
void dispose() {
    _device = null;
    super.dispose();
}
```

### 6.5 `*semver.SemVer` / `*common.Product` — gomobile Can't Marshal

**Issue:** gomobile cannot bind Go struct types with pointer fields or non-primitive types.

**Solution:** Two connect methods:
- `Connect(transport)` — passes `nil, nil` for version/product, lets OP_INFO auto-detect
- `ConnectWithInfo(transport, product string, version string)` — for simulator where OP_INFO isn't available, parses strings in Go into `*SemVer` / `*common.Product`

### 6.6 `*psbt.Packet` — In-Place Mutation Across Boundary

**Issue:** `BTCSignPSBT` modifies `*psbt.Packet` in-place (no return value). gomobile can't pass this type across the boundary.

**Solution:** Wrapper in `bridge.go`:
1. Accept `[]byte` from Kotlin
2. Parse into `*psbt.Packet` using `psbt.NewFromRawBytes`
3. Call `device.BTCSignPSBT()` (in-place mutation)
4. Serialize back to `[]byte` and return

## 7. Critical Pitfalls & Gotchas

### 7.1 Bridge Method Names

gomobile lowercases the first letter and removes the package prefix:
- Go function `BTCXPub` → Kotlin/Java: `Bridge.btcxPub(deviceId, keypath)`
- Go function `ConnectWithInfo` → Kotlin/Java: `Bridge.connectWithInfo(transport, product, version)`

### 7.2 `firmware.NewDevice` — Both or None

When passing version and product to `firmware.NewDevice`, both must be non-nil or both nil:

```go
// ✓ OK — both nil (auto-detect via OP_INFO)
device := firmware.NewDevice(nil, nil, config, comm, logger)

// ✓ OK — both provided (simulator, no OP_INFO)
device := firmware.NewDevice(version, &product, config, comm, logger)

// ✗ BROKEN — one nil, one non-nil (will panic)
device := firmware.NewDevice(nil, &product, config, comm, logger)
```

### 7.3 Flutter Layout: `FixedBottomButton` Inside `Column`

**Crash:** `FixedBottomButton`'s internal `Stack` with only `Positioned` children gets unbounded height when placed in a `Column`, causing `"size.isFinite" is not true`.

**Solution:** Use `Stack` + `Positioned` directly:

```dart
Stack(
  children: [
    Positioned.fill(child: SingleChildScrollView(...)),
    Positioned(bottom: 16, left: 24, right: 24, child: button),
  ],
)
```

### 7.4 `dart:io` Not Needed

`dart:io` was originally imported for `Platform` checks but is not used. Removed to avoid unnecessary platform dependency.

### 7.5 SVG Asset Registration

Any SVG used in the connect/sign UI must be registered in `pubspec.yaml`:

```yaml
flutter:
  assets:
    - assets/svg/bitbox02.svg
```

### 7.6 Data Flow Direction

```
Dart UI → MethodChannel("bitbox02") → Kotlin Bitbox02MethodHandler
→ executor thread → Bridge (Go) → Transport (Kotlin)
→ USB/TCP/BLE → BitBox02 device
```

MethodChannel handlers run on **main thread** → must dispatch to executor. Results must post back to **main thread** via `Handler(Looper.getMainLooper())`.

### 7.7 Wallet Import Pipeline

After pairing and xpub retrieval, wallet import uses the existing pipeline:

```dart
// 1. Generate name
final name = getNextThirdPartyWalletName(WalletImportSource.bitbox02, existingNames);

// 2. Create WatchOnlyWallet
final wallet = WalletAddService().createExtendedPublicKeyWallet(
  xpub, name, fingerprint,
  importSource: WalletImportSource.bitbox02,
);

// 3. Sync to database
final result = await walletProvider.syncFromThirdParty(wallet);

// 4. Navigate
if (result.result == WalletSyncResult.newWalletAdded) {
  Navigator.pushNamed(context, '/wallet-detail', arguments: {
    'id': result.walletId, 'entryPoint': kEntryPointWalletHome,
  });
}
```

### 7.8 Noise Key Persistence

Config keys (Noise static keypair, device pubkeys) are stored in-memory in Go (`inMemoryConfig`). They survive as long as the native process is alive. For app restart persistence, `SaveConfig`/`LoadConfig` serializes to JSON and can be stored in Flutter's `shared_preferences` or `flutter_secure_storage`.

**Current state:** Not yet wired to Flutter persistent storage — keys are lost on app restart.
